## 1. Цель, контекст и критерии готовности (DoD)

### Что создаём и для кого
Веб-приложение — **личный интерактивный дневник атмосферы («процедурная синестезия»)** для хакатона **REC GENESIS HACKATHON (трек ArtTech, сдача до 22 ноября 2026, 23:59 по времени Астаны)**[cite: 1, 4].  
Целевая аудитория — люди, которые хотят сохранять не просто снимки в галерее, а **ощущение прожитого дня**, чтобы вернуться к нему через месяц или год и снова его почувствовать[cite: 1, 5].

### Главная концепция продукта
Вместо генерации случайных картинок нейросетями система берёт **настоящие фотографии пользователя**, текст о дне и музыку, превращая их в живой **интерактивный арт-слайд (карточка 4:5)** на базе WebGL/GLSL-шейдеров и реального аудиоанализа (DSP)[cite: 2, 3]. Все записи подчиняются единой визуальной системе (4 художественных режима), сохраняются в отдельные папки с короткими осмысленными названиями (3–7 слов) и складываются в единый архив[cite: 1, 2, 3].

### Ключевые продуктовые фичи
1. **Эмоциональная погода карточки:** подбирается по визуалу фотографий и настроению дня/архива (без внешних погодных API) и рендерится как процедурный слой поверх фото (`warm_haze`, `mist`, `rain_glass`, `wind_sparks`, `clear_light`).
2. **Автоподбор музыки из Spotify + 30-сек фрагмент:** по умолчанию система сама анализирует текст, фото и контекст архива, подбирает трек из каталога Spotify и подгружает официальный 30-секундный MP3-фрагмент (с fallback через Deezer/iTunes, если у Spotify `preview_url == null`) для DSP-анализа (`librosa`) и аудиореактивности. Рядом есть переключатель **«Указать свой трек»** (ссылка или аудиофайл) для соблюдения минимальных требований кейса[cite: 3].
3. **Эффект выцветания (патина времени) и сортировка архива:** старые записи в архиве визуально выцветают (бумажная сепия, зерно, снижение насыщенности), но плавно «оживают» при наведении или открытии. В архиве есть ползунок демонстрации времени (`Сейчас → +1 год`) и фильтрация/сортировка по настроению (`Valence × Energy`, ритм, хронология).
4. **Шаринг и «Лупа воспоминания»:** генерация публичных read-only ссылок на отдельный день (`/share/day/:token`) или весь архив (`/share/archive/:token`), экспорт открытки (PNG) и видео (15 сек), а также зум фотографий (до 4x) с кнопкой удержания **«Оригинал / Арт-слой»**.
5. **Озвучка дня (бонус) + X-Ray объяснимость:** синтез речи под атмосферу дня с авто-дакингом музыки при воспроизведении голоса[cite: 1, 3] и выдвижная панель **«Почему день выглядит так?»** с прозрачным объяснением связи текста, фото и музыки[cite: 2, 5].

### Критерии готовности (Definition of Done)
Продукт считается готовым, когда:
- Пользователь создаёт день (текст + 1–5 фото; музыка автоподбирается из Spotify или загружается вручную) и получает живой 4:5 арт-слайд с озвучкой, погодой и реальной аудиореактивностью[cite: 1, 3].
- На диске создаётся реальная папка дня с названием 3–7 слов (`/vault/{slug}/`), содержащая исходники, JSON-паспорт и озвучку, доступная для скачивания в `.zip`[cite: 1, 3].
- Работают стартовый архив с фильтрами/сортировкой по настроению и выцветанием, страница папки дня, X-Ray панель, зум фото и read-only шаринг.
- В базе предзаполнено **5–7 контрастных дней** с разными датами, которые в ленте выглядят как страницы одного дневника[cite: 2, 3, 4].
- Проект собирается без ошибок (`npm run build`, `pytest`) и запускается по инструкции из `README.md`[cite: 4].

## 2. Стек технологий

### Frontend (`/frontend`)
- **Runtime / Bundler:** Node.js `20.x+`, Vite `5.4+`
- **Язык и UI:** React `18.3+`, TypeScript `5.5+`, Tailwind CSS `3.4+`
- **Стейт и роутинг:** Zustand `4.5+`, React Router `6.26+`
- **Графика и анимации:** Three.js `0.169+` (GLSL Fragment Shaders для 4 стилей + погода + патина), Framer Motion `11.11+`, `lucide-react` `0.450+`
- **Аудио и медиа:** Web Audio API (`AnalyserNode` + `GainNode` для авто-дакинга), `MediaRecorder` API (экспорт видео), `react-zoom-pan-pinch` `3.6+`

### Backend (`/backend`)
- **Runtime / API:** Python `3.12+`, FastAPI `0.115+`, Uvicorn `0.32+`, Pydantic `2.9+`, `python-multipart` `0.0.12+`
- **БД и файлы:** SQLite (`sqlite3` / SQLAlchemy `2.0+`), локальное папочное хранилище `/vault/`
- **AI / VLM:** `google-genai` `0.6+` (Gemini 2.5 Flash — мультимодальный анализ текста + фото + эмоциональной погоды + подбор 5 треков в Structured JSON; допустима альтернатива `openai` `1.50+`)
- **Компьютерное зрение (CV):** `opencv-python-headless` `4.10+`, `Pillow` `10.4+`, `scikit-learn` `1.5+` (K-Means извлечение 4–5 доминирующих цветов), `numpy` `1.26+`
- **Аудиоанализ (DSP):** `librosa` `0.10.2+`, `soundfile` `0.12+` (BPM, RMS-энергия, спектральная яркость, лад major/minor)
- **Музыкальные API:** `httpx` `0.27+` → Spotify Web API (Client Credentials Search), Deezer Public Search API и iTunes Search API (гарантированный fallback на официальные 30-сек превью)
- **Озвучка (TTS):** `edge-tts` `6.1+` (подбор голоса, `rate` и `pitch` под атмосферу дня)
- **Тесты:** `pytest` `8.3+`, `pytest-asyncio` `0.24+`

## 5. Команды запуска, сборки и проверки

### Backend
```bash
# Установка (из корня проекта)
cd backend
python -m venv .venv
# Linux / WSL:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

```

## 6. Ограничения и запреты (Guardrails)

### Архитектурные запреты (не нарушать без согласия разработчика)
1. **Не менять контракт `Memory DNA JSON`** (имена полей и типы) в одностороннем порядке — сначала согласовать изменения.
2. **Не генерировать изображения нейросетями (Flux, DALL-E, Midjourney)** взамен фото пользователя. Визуал всегда строится из реальных фотографий через параметрические GLSL-шейдеры и единую сетку 4:5[cite: 2, 3].
3. **Не подключать внешние погодные API (Open-Meteo, OpenWeather).** Погода карточки определяется исключительно по фотографиям и настроению дня/архива.
4. **Не использовать примитивный хардкод цветов («грустно = синий»)**[cite: 5]. Базовая палитра всегда извлекается алгоритмом K-Means из фотографий дня и лишь мягко гармонизируется.
5. **Не удалять режим ручного ввода трека.** Автоподбор Spotify включён по умолчанию, но пользователь обязан иметь возможность прикрепить свою песню (ссылкой или файлом)[cite: 3].
6. **Не трогать чужие модули за пределами текущего этапа MVP** и не рефакторить весь проект без запроса.
7. **Не коммитить секреты:** все ключи API хранятся строго в `.env` (добавлен в `.gitignore`).

### Обязательные правила кейса хакатона (Юридика и этика)
1. **Авторские права на музыку:** категорически запрещено скачивать, хранить на сервере или раздавать полные чужие треки[cite: 5]. Использовать только официальные 30-секундные превью API, ссылки/эмбеды на Spotify или аудио со свободной лицензией[cite: 5].
2. **Голоса и озвучка:** использовать только синтезированные голоса (`edge-tts`) или голоса согласившихся участников команды; запрещено клонировать голоса реальных людей без согласия[cite: 5].
3. **Никакой медицинской/психологической диагностики:** в промптах, UI и панели X-Ray запрещены формулировки вроде «признаки депрессии / тревожного расстройства / выгорания»[cite: 5]. Использовать только художественные и атмосферные описания («меланхоличная интонация», «высокий ритм событий»).
4. **Художественные референсы:** вдохновляться техниками и направлениями (импрессионизм, супрематизм, японский минимализм, 35mm кино), не копируя конкретные работы современных художников[cite: 2, 5].
5. **Единый тон названий папок:** строго 3–7 слов на русском языке, созерцательный стиль без восклицательных знаков и кликбейта[cite: 3].

## 7. Поэтапный план разработки (MVP Roadmap)

> **Инструкция для ИИ-агента:** Выполняй **ровно 1 этап за итерацию**. После завершения этапа:
> 1) выведи список созданных/изменённых файлов;
> 2) запусти команды проверки (`pytest` / `tsc --noEmit` / `npm run build`);
> 3) дождись подтверждения пользователя перед переходом к следующему этапу.

### Этап 0 — Каркас репозитория и контракты данных
- Создать структуру директорий `/backend`, `/frontend`, `/vault`, `.env.example`, `.gitignore`.
- Реализовать `backend/app/schemas/memory.py` и `frontend/src/types/memory.ts` по единому контракту (Раздел 4).
- Подготовить `frontend/src/mocks/sampleDays.ts` (3–4 контрастных дня с разными датами и режимами).
- **Проверка:** `uvicorn` отвечает `{"status": "ok"}` на `/health`, `npm run build` проходит без ошибок.

### Этап 1 — Ядро бэкенда: VLM, палитра фото, погода и хранилище папок
